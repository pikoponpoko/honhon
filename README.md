# HonHon

同人誌印刷所へそのまま入稿できる冊子組版アプリ。現在はブラウザ版のみ。

公開版（https://honhon.pikoponpoko.workers.dev）はブラウザからアプリとしてインストールできる（PWA。Chrome／Edgeはアドレスバーのインストールボタン、Safariは「Dockに追加」／「ホーム画面に追加」）。manifest・service worker・アイコンは `src/pwa/` にあり、`scripts/build.sh` が `dist/` に置く。

## 機能

- 本文・表紙（表1／背／表4）書類、右綴じ／左綴じ、モノクロ／カラー
- 判型：B4・A4・AB・B5・菊・A5・四六・B6・新書・文庫・正方形、縦長／横長、任意サイズ（変形）
- 印刷所プリセット：オレンジ工房（漫画・イラスト本／小説本）、グラフィック、ちょ古っ都製本工房
  - 塗り足し・安全域・ノンブル規定（サイズ・位置・隠しノンブル）・対応サイズ・ページ数をプリフライトで検査
  - 背幅計算（オレンジ工房／ちょ古っ都の用紙厚）
  - 入稿ファイル名の自動命名（01.png、graphic_01、honbun.pdf、hyousi01 など）
- 文字・画像・図形フレーム。縦組み（禁則、句読点ぶら下げ、2桁縦中横、約物回転）と横組み
  - 紙面上で直接入力、テキストフレームの連結・自動流し込み（ページ自動追加）、段組、テキストファイル読み込み（UTF-8／Shift_JIS）
  - 画像：PNG・JPEG・PSD（グレー・RGB・CMYK・2階調、非圧縮／RLE）、拡大率・位置調整。ファイルから配置した画像は外部アプリで保存すると自動更新（Chrome／Edge）
  - 整列（版面・仕上がり・塗り足し基準）、ページの複製・並べ替え
- 自動台割（扉・目次・本文・奥付などの構成から、4／8／16ページ単位で白ページを補って作成。page.plan に保存）
- 目次・奥付：デザイン（目次7種：罫線・リーダー・大きい数字・帯・縦帯・タイル・縦組み／奥付5種：罫線・中央・枠・太罫・縦組み）を実際の内容の見本から選んで作成。目次の項目は台割のタイトル（なければ太字・大きい文字の1行目）から読み込み、ページ番号はページの移動に追従（作り直すと反映）。作成した要素だけを置き換えるので何度でも作り直せる
- ノンブル（小口側・中央・隠しノンブル、ページごとの非表示）
- 入稿データ書き出し：PDF（1ファイル／1ページずつ）、PNG、TIFF（グレー／CMYK）。複数ファイルはZIP
  - 塗り足しあり／なし（仕上がりサイズ）、日本式トンボ、TrimBox／BleedBox、PDF/X-1a:2001 の OutputIntent（Japan Color 2001 Coated）
  - モノクロ：DeviceGray 600dpi／カラー：DeviceCMYK 350dpi（版ごとに描画、K100文字はK版のみ）
  - ページはラスタ化して格納（フォント埋め込み不要）
- 家庭用プリンター印刷：中綴じ面付け（4の倍数に白ページ補完）／1ページずつ、用紙自動選択（A4・B5）と縮小、両面の短辺・長辺とじに合わせた裏面回転、手動両面（表面・裏面を別ファイル）、断裁トンボ・折り位置、テスト用紙（表裏の向き・100mm実寸確認）、用紙端に近い文字・フチなし前提の塗りの警告
- Dropboxバックアップ（claude.ai のお試し版のみ。Dropboxコネクタ経由で `/HonHon` に保存・復元（旧 `/Thinbook` のバックアップも復元可）、10分ごとの自動バックアップ）
- 台割：表計算風の台割表（種類・タイトル・メモ、行の挿入／削除／並べ替え、Excel等からの貼り付け）。手書きの台割ラフを撮影した画像をClaudeで解析して台割に変換し、「冊子に反映」でページ数をそろえ、扉・目次・本文・イラスト・奥付の叩き台を作成
  - 台割の記入用紙（A4、1枚32ページ、ページ番号・種類チェック欄・タイトル欄・メモ欄）をPDFで出力でき、この用紙を前提に読み取る。複数枚の写真をまとめて読み込める
  - claude.ai上のお試し版はそのまま解析可能。単体のブラウザ版ではAnthropic APIキーが必要（ブラウザ内にのみ保存）
- 仮の本：判型どおりの見開きでページをめくって確認（中綴じ／無線綴じ、ノドの隠れ、表紙と背の読み込み、実寸表示）
- プリフライト：文字あふれ、塗り足し不足、断裁線付近の文字、低解像度画像、ページ数
- Excel（.xlsx）の編集：既存ファイルを開いてセルの値・数式を編集し、同じ形式で保存
  - 編集したシートの XML だけを書き換え、グラフ・画像・コメント・入力規則・書式などその他の部品は元のバイト列のまま保存
  - 共有数式は編集時に各セルの数式へ展開、数式を変えた場合は calcChain を外し、開いたときに再計算させる（fullCalcOnLoad）
- 頒布（イベント）：参加予定イベントの日程・申込／入稿締切、頒布物ごとの価格と搬入数、会計（お釣り計算）、集計（売上・頒布数・残部・手元現金）、CSV書き出し、反省メモ。データはブラウザ内に保存、JSONでバックアップ可
- スライド（16:9）：テーマ（配色・フォント）、レイアウト21種（タイトル／タイトル中央／タイトル帯／表紙画像／区切り／区切り左／区切り番号／本文／見出し左／一文／一文左／2段／カード／画像／画像右／全面画像／画像大／画像大小／画像6枚／数字／数字左）、構成のひな形（提案／報告／紹介／作家の自己紹介／作家の作品紹介／作家の進捗報告。作家用は発表者ノートに話す内容と目安の秒数入り）、構成テキストから一括生成、Claudeに構成を相談（Artifact版のみ）
  - 構成のカード表示：1枚のカードが1スライド。区切りごとの列にドラッグで並べ替え（列の間の移動、区切りは列ごと移動、Alt＋矢印キーでも可）、クリックで見出し・本文・レイアウトを編集。「保留」の列のカードはスライドにせず書類に残す。反映前の構成も書類に保存され、次に開くと続きから編集できる。テキスト表示と切り替え可
  - レイアウト案：スライドの内容（箇条書きの数・数字・画像・文字量）から合うレイアウトを最大6案、実際の内容で描いた見本で提示。選ぶと内容を移し替え、あふれる文字は縮小。表示しきれない内容は保持し、別のレイアウトに戻すと復元
  - 後から足した文字・画像・図形や、読み込んだ .pptx のスライドにも使える。見出しと本文は枠に入れ、残りの文字は本文の下に並べ、画像・図形（重なった図形と文字はひとまとまり）は縦横比を保って画像枠や空いた段に配置。グループ内の図形など .pptx で動かせない要素はそのまま
- DM：はがき（100×148mm）・A6・A5・A4、縦／横。作品画像を選ぶとレイアウトの画像枠に入る。デザイン面のレイアウト5種（作品画像＋情報／全面の作品画像＋帯／余白のある作品画像／キーカラーの地／文字のみ）、裏は宛名面・案内・キーカラー・作品画像。宛名面は「郵便はがき」表示・切手枠・郵便番号枠（右端基準の私製はがき位置）、下半分に案内と差出人（はがき・A6の縦のみ）。色は作品のキーカラーの役割。名刺と同じ入稿PDF（塗り足し3mm・トンボ・CMYK 600dpi、ファイル名 `*_dm.pdf`）と既存データの読み込みを使う
- PowerPoint（.pptx）書き出し：テキスト・図形・画像・動画・発表者ノートを編集可能な形で出力
- 既存 .pptx の読み込みと非破壊保存：変更したスライドのXMLだけを書き換え、他のパーツは元のバイト列のまま再格納（テキスト、位置・サイズ、文字サイズ・色・太さ・フォント、削除、追加、画像差し替えに対応）
- 動画フレーム：埋め込み（PowerPoint 2010以降の形式）、既存 .pptx の動画の読み込み
- プレゼン練習（発表者ビュー）：.pptx の動画を設定どおりに再生（自動／クリック時、トリミング、音量、ループ。動画のクリックで一時停止・再開、別ウィンドウと同期）。非表示スライドは飛ばす

## 構成

- `src/app.html` — アプリ本体（単一ファイル、ライブラリ不使用）。claude.ai Artifact としてそのまま公開できる形式
- `scripts/build.sh` — 単体で開ける `dist/index.html` を生成
- `scripts/test-reliability.mjs` — 保存・読み込み・画像書き出し・読み込み値の検証（Node.js 20以降）
- `tests/smoke.js` — 実ブラウザ（Playwright）で新規作成・自動保存・開き直し・PDF書き出し・スマホ幅を確かめる

```sh
./scripts/build.sh
open dist/index.html
```

紙面上の本文も入力中にブラウザ内へ自動保存し、ヘッダーに保存状態を表示する。書類の新規作成・ファイル読み込み前には、現在の作品の復元用コピーをこの端末に1件保存する。HonHonメニューの「前の作品を復元」から戻せる。ブラウザ内の保存は端末間で同期されないため、大切な作品は「保存」から編集用ファイルも保存する。

回帰テストは `node scripts/test-reliability.mjs` で実行する。本体の関数を抽出し、DOM・ストレージ・キャンバスを代替して保存順序や読み込み失敗時の状態を検証する。実ブラウザでの操作は `tests/smoke.js` で確かめる（`dist/` を `http://localhost:8765/` で配信してから `node tests/smoke.js`）。どちらもPRとmainへのpushでGitHub Actionsが実行する。印刷品質やOffice互換性の検証は別途行う。
